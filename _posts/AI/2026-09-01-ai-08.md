### 에이전트 스킬이란 무엇인가

에이전트 스킬은 AI 코딩 에이전트에게 특정 작업을 어떻게 수행해야 하는지 알려주는 재사용 가능한 지침 모음입니다. 이 블로그가 매 글마다 자동으로 불러오는 `blog-writing-guide`나 `task-observer` 같은 것도 같은 개념입니다.

형식은 `SKILL.md`라는 마크다운 파일 하나로 정해져 있습니다. 파일 맨 위에 YAML 프론트매터로 `name`과 `description`을 적고, 본문에 실제 지침을 자연어로 풀어 씁니다. `metadata.internal: true`를 넣으면 일반 검색에는 노출되지 않는 내부용 스킬로 관리할 수도 있습니다.

문제는 이 스킬 파일을 에이전트마다 요구하는 폴더 경로가 다르다는 점입니다. 클로드 코드는 `.claude/skills/`, 다른 에이전트는 또 다른 경로를 씁니다. 스킬을 하나 만들어도 여러 에이전트에서 쓰려면 매번 경로를 맞춰 복사해야 했는데, `skills` CLI가 이 변환과 배치를 대신 처리합니다.

---

### 설치는 npx 명령 한 줄, 소스는 깃허브 외에도 다양하게 지원한다

가장 기본적인 사용법은 다음과 같습니다.

```bash
npx skills add vercel-labs/agent-skills
```

이 한 줄이면 `vercel-labs/agent-skills` 저장소 안의 스킬들을 찾아서 현재 프로젝트에 맞는 경로로 설치합니다. 소스로 넘길 수 있는 값은 깃허브 shorthand 말고도 여러 형태를 지원합니다.

```bash
# 깃허브 전체 URL
npx skills add https://github.com/vercel-labs/agent-skills

# 저장소 안의 특정 스킬 경로로 바로 지정
npx skills add https://github.com/vercel-labs/agent-skills/tree/main/skills/web-design-guidelines

# 깃랩 URL
npx skills add https://gitlab.com/org/repo

# 깃허브가 아닌 일반 git URL
npx skills add git@github.com:vercel-labs/agent-skills.git

# 로컬 경로
npx skills add ./my-local-skills
```

설치를 실제로 실행하지 않고 먼저 훑어보고 싶다면 `use` 서브커맨드로 프롬프트만 뽑아 파이프로 넘길 수 있습니다.

```bash
npx skills use vercel-labs/agent-skills@web-design-guidelines | claude
```

주요 플래그는 이렇습니다. `-g` 또는 `--global`을 붙이면 프로젝트 폴더 대신 사용자 홈 디렉터리에 설치되고, `-a`로 특정 에이전트만 골라 설치할 수 있습니다. `-s`로 저장소 안의 특정 스킬만 선택하고, `--copy`를 쓰면 기본값인 심볼릭 링크 대신 파일을 그대로 복사합니다. `-y`는 설치 확인 프롬프트를 건너뛰고, `--all`은 찾은 모든 스킬을 지원하는 모든 에이전트에 한 번에 설치합니다.

설치 위치는 심볼릭 링크가 기본값입니다. 원본 스킬 파일 하나를 여러 에이전트 경로에서 링크로 참조하는 구조라, 스킬 내용을 업데이트하면 그 스킬을 설치한 모든 곳에 한 번에 반영됩니다.

### 설치하고 끝이 아니라 list, find, update 같은 관리 명령도 이어진다

설치 이후 스킬을 관리하는 명령도 따로 있습니다.

```bash
npx skills list        # 현재 설치된 스킬 목록 확인
npx skills find react  # 키워드로 스킬 검색
npx skills update      # 설치된 스킬을 최신 버전으로 갱신
npx skills remove      # 스킬 제거
npx skills init        # 새 SKILL.md 스캐폴딩
```

`find`는 인자 없이 실행하면 대화형으로 검색할 수 있고, `--owner` 플래그로 특정 계정이 올린 스킬만 필터링할 수도 있습니다. 새 스킬을 직접 만들 때는 `init` 명령이 `name`과 `description` 필드가 채워진 `SKILL.md` 템플릿을 만들어줍니다.

비공개 저장소의 스킬을 설치할 때는 별도 토큰 입력 없이 로컬에 이미 설정된 git 인증(깃허브 CLI `gh`, SSH 키 등)을 순서대로 시도합니다. `GITHUB_TOKEN`이나 `GH_TOKEN` 환경변수를 직접 지정할 수도 있습니다.

### 어떤 스킬이 있는지는 skills.sh에서 찾는다

### 에이전트마다 지원하는 기능 범위는 다르다

주의할 점은 모든 에이전트가 스킬의 모든 기능을 똑같이 지원하지는 않는다는 것입니다. 이름과 설명, 기본 지침 같은 핵심 기능은 대부분의 에이전트에서 동작하지만, `allowed-tools`로 도구 사용을 제한하는 기능이나 `context: fork`, 훅(hook) 연동 같은 고급 기능은 현재 클로드 코드와 Kiro CLI 정도에서만 지원됩니다. 다른 에이전트에 설치했을 때 프론트매터의 일부 필드가 무시될 수 있다는 뜻입니다.

CLI는 공개 저장소를 대상으로 익명 사용 통계를 수집합니다. 이 수집이 부담스럽다면 `DISABLE_TELEMETRY=1` 또는 `DO_NOT_TRACK=1` 환경변수로 끌 수 있습니다.

이미 클로드 코드에서 스킬을 프로젝트 폴더에 직접 만들어 쓰고 있다면 당장 `skills` CLI가 필요하지는 않습니다. 다만 다른 사람이 공개한 스킬을 가져오거나, 만든 스킬을 커서 같은 다른 에이전트에서도 쓰고 싶어질 때는 폴더 구조를 손으로 맞추는 대신 이 CLI 한 줄로 끝낼 수 있습니다.
