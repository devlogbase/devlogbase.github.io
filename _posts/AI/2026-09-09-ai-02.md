OpenAI가 2026년 9월 8일 ChatGPT Images 2.5를 공개했습니다. 4월에 나온 Images 2.0의 후속이고, 앱에서 쓰는 이미지 생성 모델과 개발자용 API 모델이 함께 업데이트됐습니다.

이름이 셋으로 갈라져 헷갈릴 수 있는데 정리하면 이렇습니다.

- **ChatGPT Images 2.5** : 챗GPT 앱과 웹에서 쓰는 이미지 생성 기능
- **GPT-Image-2.5 Flare** : API용 기본 모델, 빠른 일상 생성
- **GPT-Image-2.5 Sunburst** : API용 고정밀 모델, 편집 정확도 우선

*OpenAI가 9월 8일 올린 ChatGPT Images 2.5 발표 페이지*
{: style="text-align: center;"}

OpenAI는 매주 챗GPT와 API를 합쳐 30억 장이 넘는 이미지가 만들어진다고 밝혔습니다. 그 사용량 위에서 속도와 편집 정확도를 손본 업데이트입니다.

### 달라진 점

**생성 속도가 최대 50% 빨라졌습니다.** Images 2.0 대비 이미지 생성 지연 시간을 최대 절반으로 줄였습니다. 결과물을 여러 번 고쳐가며 완성하는 작업에서 대기 시간이 줄어듭니다.

**참조 사진 속 인물이 잘 유지됩니다.** 사진 한 장을 넣고 배경이나 스타일, 구도를 바꾸라고 시켰을 때 얼굴이나 특징이 원본과 덜 어긋납니다. 조명과 질감도 이전보다 자연스럽게 나옵니다.

**여러 번 편집해도 앞선 수정이 남습니다.** 대화를 이어가며 "이번엔 셔츠 색만 바꿔줘", "이제 배경을 낮으로" 하는 식으로 계속 고칠 때, 이전 편집 결과가 무너지지 않고 쌓입니다. 요청한 부분만 바꾸고 나머지는 그대로 두는 정확도도 올랐습니다.

**복잡한 지시와 스타일을 더 잘 따릅니다.** 투명 배경이 섞인 레이아웃, 실제 정보가 들어간 이미지, 특정 화풍 지정 같은 요구를 더 안정적으로 반영합니다. 지시가 구체적으로 늘어날수록 결과가 엉뚱하게 흘러가던 문제를 줄였다고 설명합니다.

### 챗GPT에 새로 생긴 기능

모델 성능과 별개로 챗GPT 앱에 편집 도구가 몇 개 추가됐습니다.

- **스케치** : 챗GPT 안에서 직접 손으로 그림을 그려 참조로 넘깁니다. 방 배치나 옷 실루엣을 대충 그리고 스타일 설명을 붙이면 완성 이미지로 바꿔줍니다. 입력창에 `@Sketch`를 입력하면 됩니다.
- **템플릿** : 포스터, 굿즈, 전단, 제품 사진처럼 자주 쓰는 형식을 골라 시작합니다. 빈 화면 대신 형식이 잡힌 상태에서 문구와 요소만 채웁니다.
- **이미지 댓글** : 생성된 이미지 위에 직접 코멘트를 찍어 그 지점만 집중적으로 고칩니다.
- **프롬프트 공유** : 이미지를 공유할 때 만든 프롬프트를 같이 넘겨, 받은 사람이 자기 사진과 정보로 같은 아이디어를 돌려볼 수 있습니다.

### 무료로 쓸 수 있나

됩니다. ChatGPT Images 2.5는 발표 당일부터 ChatGPT, ChatGPT Work, Codex 사용자 전체 요금제에 순차 적용됩니다. 무료 요금제도 포함이고 데스크톱, 모바일, 웹 모두에서 씁니다. 무료 사용자는 하루 생성 횟수 제한이 유료보다 낮습니다.

### 개발자용 두 모델, Flare와 Sunburst

API에는 모델이 두 개 추가됐습니다. 둘 다 텍스트와 이미지를 입력받아 이미지를 만들고, `low` `medium` `high` `xhigh` `max` `auto` 품질 옵션을 지원합니다. Image API에서 모델 이름으로 직접 부르거나 Responses API의 이미지 생성 도구로 씁니다.

*OpenAI가 밝힌 Flare와 Sunburst의 용도 구분*
{: style="text-align: center;"}

| 구분 | GPT-Image-2.5 Flare | GPT-Image-2.5 Sunburst |
| --- | --- | --- |
| 위치 | API 기본 모델 | 고정밀 모델 |
| 성능 등급 | Higher | Highest |
| 속도 | 매우 빠름 | 보통, 생성 시간 김 |
| 겨냥하는 작업 | 소셜과 크리에이터 콘텐츠, 제품 이미지, 비주얼 검색, 프로토타이핑, 대량 생성 | 캠페인 크리에이티브, 다듬어진 제품 이미지 등 편집 정확도가 중요한 작업 |
| GPT-Image-2 대비 | 같은 품질을 50% 낮은 지연시간으로 | 정밀도를 한 단계 더, 대신 느림 |

정리하면 대부분은 Flare로 시작하고, 편집을 여러 번 반복하며 브랜드 톤을 정확히 지켜야 하는 작업에서만 Sunburst를 씁니다.

### API 가격

두 모델의 토큰 단가는 같습니다.

*API 문서에 적힌 Flare 가격. Sunburst도 같은 단가다*
{: style="text-align: center;"}

| 항목 | 100만 토큰당 |
| --- | --- |
| 텍스트 입력 | 5달러 |
| 텍스트 캐시 입력 | 1.25달러 |
| 이미지 입력 | 8달러 |
| 이미지 캐시 입력 | 2달러 |
| 이미지 출력 | 30달러 |

이미지를 출력하는 모델이라 텍스트 출력은 청구되지 않습니다.

일부 매체가 "API 가격 2배 인상"으로 보도했는데, OpenAI API 문서에는 토큰 단가가 GPT-Image-2와 동일하다고 명시돼 있습니다. 다만 GPT-Image-2용 토큰 계산기로는 2.5의 토큰 소모량을 추정할 수 없다고 안내합니다. 이전 GPT-Image-2 기준으로 1024픽셀 이미지 한 장이 품질 옵션에 따라 대략 2센트에서 19센트 사이였고, 단가가 같으니 2.5도 비슷한 범위로 보면 됩니다. 정확한 장당 비용은 [OpenAI 가격 페이지](https://openai.com/api/pricing/)에서 확인해야 합니다.

### 갈아탈 만한가

이미지 생성 AI 경쟁은 구글의 Gemini 이미지 모델, 마이크로소프트의 MAI-Image-2.5 등으로 좁혀져 있습니다. 참조 사진 속 인물을 유지하며 배경만 바꾸는 작업, 그리고 대화를 이어가며 조금씩 고쳐나가는 편집에서 이번 업데이트의 강점이 큽니다. 반대로 완전히 새로운 장면을 한 번에 뽑는 용도라면 기존에 쓰던 도구에서 굳이 옮길 이유는 적습니다.

챗GPT를 이미 쓰고 있다면 별도 설정 없이 바로 나은 결과를 받게 되므로, 우선 써보고 판단하는 편이 빠릅니다.

### 정리

ChatGPT Images 2.5는 새 장면을 만드는 능력보다 이미 있는 이미지를 지키면서 고치는 능력에 초점을 둔 업데이트입니다. 속도는 최대 50% 빨라졌고, API는 빠른 Flare와 정밀한 Sunburst로 나뉘며 토큰 단가는 GPT-Image-2와 같습니다. 무료 요금제를 포함한 모든 챗GPT 사용자에게 적용됩니다.

자세한 내용은 [OpenAI 공식 발표](https://openai.com/index/introducing-chatgpt-images-2-5/)와 [API 모델 문서](https://developers.openai.com/api/docs/models/gpt-image-2.5-flare)에 있습니다.

### 자주 묻는 질문

**Flare와 Sunburst 중 뭘 써야 하나요.**
대부분은 Flare입니다. Flare가 API 기본 모델이고 속도와 품질 균형이 좋습니다. 같은 이미지를 여러 번 편집하며 브랜드 톤이나 세부 요소를 정확히 지켜야 하는 작업에서만 Sunburst를 고려하면 됩니다. 대신 Sunburst는 생성 시간이 더 깁니다.

**ChatGPT Images 2.5와 API 모델은 같은 건가요.**
성능 개선의 뿌리는 같지만 제품이 다릅니다. 앱에서 쓰는 건 ChatGPT Images 2.5이고, 코드로 부르는 건 GPT-Image-2.5 Flare 또는 Sunburst입니다. 스케치나 템플릿 같은 앱 기능은 API에 없습니다.

**GPT-Image-2로 만들던 파이프라인을 바꿔야 하나요.**
토큰 단가가 같아 비용 부담은 비슷하고, 모델 이름만 `gpt-image-2.5-flare`로 바꿔 호출하면 됩니다. 다만 토큰 소모량 추정치가 달라질 수 있으니 전환 전에 실제 호출로 비용을 확인하는 편이 안전합니다.

**생성 속도가 4배 빨라졌다는 말도 있던데요.**
OpenAI 공식 발표문에 명시된 수치는 Images 2.0 대비 최대 50% 낮은 지연 시간입니다. 일부 보도에서 나온 4배는 챗GPT 환경의 체감 속도를 인용한 것으로, 측정 기준이 다릅니다. API 문서 기준으로는 50% 쪽이 정확합니다.
