코덱스 CLI를 0.158.0으로 업데이트한 뒤 Windows에서 빈 터미널 창이 프롬프트를 입력할 때마다 잠깐 열렸다 닫힌다는 보고가 GitHub에 여러 건 올라와 있습니다. 시작할 때 `codex-windows-sandbox-setup.exe` 창이 뜨고, 일부 창은 몇 초 동안 남아 있고, 0.157.1에서는 입력 포커스를 가져간다는 보고도 있습니다.

문제는 0.158.0에서 처음 생긴 것이 아니라 0.157.0부터 보고됐고 9월 29일 기준으로 관련 이슈는 모두 열려 있습니다. 어떤 버전에서 나는지, 왜 나는 것으로 보이는지, 지금 할 수 있는 임시 대처가 무엇인지 이슈 내용을 기준으로 정리했습니다.

{: style="text-align: center;"}

코덱스 0.158.0은 9월 28일에 나온 버전입니다. 제가 확인한 릴리스 노트 요약에는 전체 화면 TUI의 복사와 붙여넣기 설정, MCP 서버 인증 지원, Windows 샌드박스 실패 수정 등이 실려 있고 콘솔 창 문제는 언급되지 않았습니다.

보고된 증상은 다음과 같습니다.

- 프롬프트를 제출할 때마다 콘솔 창 여러 개가 짧게 열렸다 닫힙니다. 도구를 호출하지 않는 단순한 질문에서도 나타납니다 ([#49122](https://github.com/openai/codex/issues/49122)).
- 시작할 때와 사용하는 도중에 `codex-windows-sandbox-setup.exe` 창이 뜹니다. 어떤 창은 몇 초 동안 남아 있습니다 ([#48945](https://github.com/openai/codex/issues/48945)).
- 창이 3개에서 5개씩 묶여 나타나며 타이핑 중에 포커스를 가져갑니다 ([#48440](https://github.com/openai/codex/issues/48440), 0.157.1 보고).

제가 확인한 이슈는 모두 Windows 환경이었습니다. macOS와 Linux에서 같은 증상이 나왔다는 보고는 찾지 못했습니다.

## 터미널 창이 뜨는 버전과 추정 원인

*GitHub openai/codex 이슈 보고를 정리해 직접 그린 도표*
{: style="text-align: center;"}

| 버전 | 보고된 내용 | 근거 |
|---|---|---|
| 0.156.x | 0.157.0에서 이 버전으로 내리자 사라졌다는 보고가 있으나, 제 PC에서는 내려도 창이 그대로 뜸 | [#48087](https://github.com/openai/codex/issues/48087) |
| 0.157.0 | 셸 명령을 실행할 때 창이 반복해서 뜸 | [#48059](https://github.com/openai/codex/issues/48059) |
| 0.157.1 | 에이전트가 명령을 실행할 때마다 창이 깜빡임 | [#48540](https://github.com/openai/codex/issues/48540) |
| 0.158.0 | 시작할 때 샌드박스 설정 창이 뜨고 프롬프트마다 깜빡임 | [#48945](https://github.com/openai/codex/issues/48945), [#49122](https://github.com/openai/codex/issues/49122) |

원인은 공식적으로 확인되지 않았고 이슈에 올라온 분석은 두 갈래입니다.

첫째는 백그라운드 서버입니다. 0.157.0 보고에는 `codex.exe`가 띄운 백그라운드 서버가 `powershell.exe`를 실행하고 그 아래에서 `conhost.exe`가 만들어지며 창이 보인다는 프로세스 흐름이 적혀 있습니다. 다른 이슈의 분석은 콘솔 없이 도는 서버가 창 숨김 플래그(`CREATE_NO_WINDOW`) 없이 자식 프로세스를 만들면 Windows가 새 콘솔을 열고 그 콘솔을 Windows Terminal이 창으로 보여 준다는 설명입니다.

둘째는 샌드박스 설정 프로그램입니다. 0.158.0 보고자는 샌드박스 갱신이 반복해서 기록되고, 시작할 때와 사용 중에 `codex-windows-sandbox-setup.exe` 창이 뜬다고 적었습니다. 확정된 원인은 아니고 실행 파일이 보이는 콘솔로 뜨는 것으로 의심한다는 설명입니다. 샌드박스 방식을 elevated에서 unelevated로 바꿔 봤지만 깜빡임은 그대로였다는 보고도 있습니다.

## 코덱스 터미널 창 뜨는 문제 임시 해결법 3가지

세 방법 모두 OpenAI가 창 문제의 해법으로 안내한 내용은 아닙니다. 방법 1과 방법 2는 제 Windows PC에서 직접 확인했고, 방법 3은 확인하지 못했습니다.

### 방법 1, codex --no-daemon으로 백그라운드 서버 끄고 실행하기

제 PC에서는 `codex --no-daemon`으로 실행하자 터미널 창이 더 이상 뜨지 않았습니다. 0.157.1 보고자도 같은 플래그로 백그라운드 서버를 끄고, 같은 설정을 `features.daemon_auto_start=false`로 저장해 사용했다고 적었습니다 ([#48440](https://github.com/openai/codex/issues/48440)). 실행할 때마다 옵션을 붙이는 방식은 다음과 같습니다.

```
codex --no-daemon
```

백그라운드 서버가 창을 띄운다는 이슈의 분석과 맞는 결과입니다. Windows 10에서 0.157.1과 0.158.0이 `this CLI has no complete local package` 오류를 내며 실행되지 않을 때도 `--no-daemon`을 붙이면 실행된다는 보고가 있습니다 ([#48899](https://github.com/openai/codex/issues/48899)). 백그라운드 서버를 끄면 빠지는 기능이 있는지는 이슈에 나와 있지 않고 저도 확인하지 못했습니다.

### 방법 2, 0.156 버전으로 되돌리기

0.157.0에서 창이 반복해서 뜨던 보고자는 0.156.0으로 내리자 사라지고 다시 올리자 재현됐다고 적었습니다 ([#48087](https://github.com/openai/codex/issues/48087)).

제 PC에서는 0.156으로 내려도 창이 똑같이 떴습니다. 백그라운드 서버가 0.156에서도 창을 띄우는 환경이 있는 것으로 보이고, 롤백이 모든 환경의 해법은 아닙니다. 롤백을 시도한다면 방법 1을 먼저 써 보는 편이 좋을 것 같습니다.

현재 버전은 다음 명령으로 확인합니다.

```
codex --version
```

npm으로 설치했다면 다음과 같이 버전을 지정해 내릴 수 있습니다. 이슈에는 내리는 명령이 적혀 있지 않아 npm의 일반 문법으로 적었습니다.

```
npm install -g @openai/codex@0.156.0
```

standalone 설치 파일을 쓰는 경우의 롤백 절차는 확인하지 못했습니다. 이 경우에는 0.156.x 릴리스에서 설치 파일을 받아 다시 설치하는 방식이 될 것 같습니다.

### 방법 3, standalone 설치로 다시 설치하기

npm이 아니라 공식 standalone 설치 스크립트로 다시 설치한 뒤 cmd를 강제 종료하고 다시 켰더니 창이 사라졌다는 후기가 있습니다. 저는 이 방법을 직접 확인하지 못했고, 왜 통했는지 설명한 이슈도 찾지 못했습니다. 이전 설치본이나 이미 떠 있던 백그라운드 프로세스가 정리되면서 달라졌을 가능성이 있을 뿐입니다.

설치 명령은 코덱스 공식 README에 실린 Windows용 standalone 설치 명령과 같습니다.

```
powershell -ExecutionPolicy ByPass -c "irm https://chatgpt.com/codex/install.ps1 | iex"
```

이 명령은 `chatgpt.com/codex/install.ps1` 스크립트를 내려받아 바로 실행하고, Node.js 없이 쓰는 standalone 버전을 설치해 PATH에 추가합니다. 같은 명령을 다시 실행하면 업데이트됩니다. 설치 파일은 `releases.openai.com/codex`에서 받고, 받지 못하면 GitHub Releases로 넘어갑니다.

## 0.158.0에서 같이 보고된 다른 오류

창 문제와 별개로 0.158.0에는 몇 가지 오류가 더 올라와 있습니다.

- **마우스 문자 입력** : 터미널 위에서 마우스를 움직이면 프롬프트에 `[M#l5[M#k5` 같은 문자열이 들어갑니다. PowerShell에서 보고됐고 ([#49071](https://github.com/openai/codex/issues/49071)), IntelliJ IDEA 터미널에서는 패널 표시가 깨진다는 보고도 있습니다 ([#49029](https://github.com/openai/codex/issues/49029)). 이슈에 적힌 우회 방법은 없습니다.
- **실행 자체가 안 되는 문제** : Windows 10에서 `no complete local package` 오류가 나며 0.156.1은 정상, 0.157.1과 0.158.0은 실패합니다. 위에서 설명한 `--no-daemon`이 우회 방법으로 보고돼 있습니다.

## 코덱스 0.158 오류 수정 상태

9월 29일 기준으로 제가 확인한 이슈에는 OpenAI 담당자의 답변이나 연결된 수정 PR이 없었습니다.

개발 버전에서는 움직임이 있습니다. 0.158.0 알파 후반과 0.159.0 알파 7에서 일반 셸 명령 실행에 창 숨김 플래그가 적용돼 PowerShell 창이 사라졌다고 합니다. 그러나 대화를 시작하거나 이어 열 때 내부에서 실행하는 Git 확인 명령이 여전히 창을 띄운다는 보고가 남아 있습니다 ([#48601](https://github.com/openai/codex/issues/48601)). 알파 버전이라 정식 배포 시점은 알 수 없습니다.

새 버전이 나오면 [릴리스 페이지](https://github.com/openai/codex/releases)의 변경 내역에서 Windows 콘솔 창 항목이 있는지 확인하고 올리는 편이 좋을 것 같습니다.

## 자주 묻는 질문

### 코덱스 0.158.0 터미널 창은 Windows에서만 뜨나요?

제가 확인한 이슈는 모두 Windows였습니다. macOS나 Linux에서 같은 증상이 나왔다는 보고는 찾지 못했습니다.

### 터미널 창이 뜨면 코덱스가 해킹당한 건가요?

이슈 분석으로는 보안 문제가 아니라 자식 프로세스를 만들 때 창 숨김 처리가 빠진 버그로 보입니다. 이슈에 적힌 창의 출처도 `codex-windows-sandbox-setup.exe`, `powershell.exe`, `conhost.exe`처럼 코덱스가 실행하는 프로그램과 Windows 콘솔 구성요소입니다.

### 0.156으로 되돌리면 해결되나요?

항상 그렇지는 않습니다. 0.157.0에서 창이 뜨던 보고자는 0.156.0으로 내리자 사라졌다고 적었지만, 제 PC에서는 0.156으로 내려도 창이 그대로 떴습니다. `codex --no-daemon`으로 실행했을 때는 창이 뜨지 않았습니다.

### 코덱스 터미널 창 오류는 언제 고쳐지나요?

9월 29일 기준으로 정식 버전 수정 일정은 공개되지 않았습니다. 0.159.0 알파에서 일부 수정이 들어갔고 Git 확인 창은 남아 있다는 보고가 있어 정식 0.159 버전이 나와야 확인할 수 있을 것 같습니다.
