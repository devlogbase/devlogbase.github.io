매달 크레딧을 먼저 사는 대신, 필요한 기능만 API로 붙여 이미지와 영상을 만들고 싶다면 **OpenHiggsfield** 같은 웹 스튜디오 코드가 출발점이 될 수 있습니다. 프롬프트 입력창 하나에서 모델을 고르고 결과를 갤러리에 모으는 화면을 처음부터 구현하지 않아도 되기 때문입니다.

다만 코드가 공개되어 있다는 사실과 생성 비용이 없다는 뜻은 전혀 다릅니다. OpenHiggsfield 저장소는 UI와 생성 요청 흐름을 제공하지만 실제 이미지와 영상을 만들려면 별도의 생성 API 키와 충전 잔액이 필요합니다. 이 글은 공개된 스튜디오 코드를 검토할 때 확인할 구조와 Higgsfield API를 붙일 때의 비용·보안 기준을 함께 정리합니다.

## OpenHiggsfield는 모델이 아니라 생성 화면의 뼈대입니다

[OpenHiggsfield 저장소](https://github.com/wide-trace/open-higgsfield)는 이미지와 영상 모델을 하나의 프롬프트 바에서 고르고 모델별 설정과 생성 이력을 한 화면에서 관리하도록 만든 Next.js 기반 프로젝트입니다. 모델을 바꾸면 해상도, 길이, 오디오, 입력 미디어 같은 설정 항목도 함께 바뀌는 구성이 핵심입니다.

저장소 설명에는 이미지 8종과 영상 30종, 총 38개 모델을 카탈로그로 다룬다고 적혀 있습니다. 새 모델을 넣을 때 화면마다 옵션을 다시 만드는 대신, 모델 카탈로그의 정의를 기준으로 선택기와 설정 패널을 렌더링하는 방식입니다. 자체 서비스에 영상 생성 기능을 넣을 때 특히 유용한 부분입니다.

생성 결과는 브라우저 갤러리에 남습니다. 프롬프트와 설정을 다시 불러와 재생성하고 즐겨찾기와 선택 삭제를 할 수 있습니다. 다만 이력 화면이 있어도 원본 미디어가 영구 보관되는 것은 아닙니다. 저장소 설명도 생성 플랫폼의 결과 URL이 만료되면 과거 갤러리에 빈 항목이 생길 수 있다고 안내합니다. 서비스로 운영한다면 완성된 파일을 자체 스토리지로 복사하는 처리가 필요합니다.

여기서 한 가지는 분리해서 봐야 합니다. OpenHiggsfield라는 공개 저장소는 `wide-trace` 계정으로 제공되며 힉스필드 공식 도움말은 외부 코드나 미러를 자사가 배포·유지하지 않는다고 밝힙니다. 따라서 제품 소개나 서비스 배포 화면에서 이를 힉스필드 공식 웹 스튜디오라고 단정하기보다, 독립된 스튜디오 코드와 Higgsfield API를 연결하는 구성으로 설명하는 편이 정확합니다. 저장소 최상위 파일 목록에는 라이선스 파일도 보이지 않으므로, 상용 배포나 재배포 전에는 저장소 소유자에게 사용 조건을 확인해야 합니다.

## Higgsfield API는 구독이 아니라 잔액을 쓰는 구조입니다

Higgsfield API는 API 키 하나와 미국 달러 잔액을 기준으로 동작하는 종량제 방식입니다. [공식 API 소개](https://higgsfield.ai/blog/higgsfield-api)에 따르면 이미지 모델은 장당, 영상 모델은 출력 초당 가격을 공개하고 있습니다. 매달 생성량이 크게 달라지는 개인 프로젝트나 소규모 서비스라면 구독 크레딧보다 예산을 계산하기 쉽습니다.

영상 요금은 모델, 해상도, 오디오, 입력 방식에 따라 달라집니다. 같은 Seedance 2.5라도 텍스트에서 영상으로 만드는지, 이미지나 영상 참조를 넣는지에 따라 단가와 계산식이 바뀝니다. 공식 모델 카탈로그는 Seedance 2.5의 텍스트·이미지·참조 영상 생성 범위를 초당 0.144달러에서 0.3236달러로 표시하며 할인 전 기준이라고 설명합니다. 반면 공식 API 안내 글에는 시작 단가로 초당 0.0738달러가 표시됩니다. 가격 페이지와 모델 페이지의 표시 시점·조건이 다를 수 있으므로, 영상 하나의 예산을 잡을 때는 결제 직전 [Seedance 2.5 모델 페이지](https://console.higgsfield.ai/models/bytedance/seedance-2.5/text-to-video/playground)에서 선택한 설정의 단가를 확인해야 합니다. 실제로 이 모델 페이지에 들어가 보면 단순한 초당 요금이 아니라 토큰 단위 계산식으로 가격을 안내합니다. 입력·생성 영상의 초 수에 출력 가로세로 픽셀 수와 24fps를 곱한 값을 1,024로 나눠 토큰 수를 구하고 480p나 720p 기준 토큰 1,000개당 0.0214달러를 매기는 방식입니다.

15초 영상의 비용을 단순히 초당 단가에 15를 곱해 확정하면 안 되는 이유도 여기에 있습니다. 해상도가 올라가거나 오디오를 켜고 영상 참조를 넣는 순간 청구 기준이 달라질 수 있습니다. 프롬프트를 다듬는 단계에서는 짧은 길이와 낮은 해상도로 먼저 확인하고 승인한 장면만 최종 설정으로 생성하는 편이 지출을 통제하기 쉽습니다.

## API 키는 화면에 넣지 말고 서버에서만 처리해야 합니다

OpenHiggsfield 저장소는 생성 API 호출을 서버 액션에 모아 브라우저가 직접 생성 API와 통신하지 않도록 구성합니다. API 키를 클라이언트 자바스크립트에 넣거나 정적 웹 페이지에 그대로 배포하면, 브라우저 개발자 도구와 네트워크 요청을 통해 키가 노출될 수 있습니다.

Higgsfield의 공식 예시는 `HF_API_KEY_ID`와 `HF_API_KEY_SECRET`을 서버 환경 변수로 두고 `Authorization` 헤더에 조합합니다. 키를 발급하는 순서는 다음처럼 잡으면 됩니다.

1. Higgsfield API 콘솔에서 프로젝트용 키를 발급하고 사용할 잔액 충전 또는 빌링 설정을 확인합니다.
2. 키 값은 로컬 개발 환경의 `.env` 파일이나 배포 환경의 비밀 변수에만 저장합니다.
3. `.env`는 Git 추적에서 제외하고 예시 파일에는 변수 이름만 남깁니다.
4. 프런트엔드는 자체 서버 엔드포인트에 생성 요청을 보내고 서버가 Higgsfield API에 요청을 전달합니다.
5. 반환된 요청 ID와 상태 URL을 저장한 뒤, 완료·실패·검열·취소 상태를 구분해 화면에 표시합니다.

API 키를 공개 저장소의 코드나 캡처 이미지에 넣는 실수는 특히 위험합니다. 키가 노출됐다면 삭제만 하지 말고 즉시 폐기한 뒤 새 키를 발급해야 합니다. 테스트용 키도 잔액과 생성 권한을 가진 자격 증명이라는 점은 같습니다.

## Soul 2 이미지에서 Seedance 2.5 영상으로 이어지는 흐름

나만의 AI 영상 앱을 만들 때 가장 단순한 흐름은 이미지 한 장을 만든 뒤 영상 생성의 출발점으로 쓰는 방식입니다. Higgsfield API 카탈로그에서 Soul 2는 이미지 한 장당 시작가 0.0032달러로 소개됩니다. 인물·제품·배경의 구도를 먼저 잡는 용도로 비용 부담이 비교적 작습니다.

그다음 Seedance 2.5의 이미지 투 비디오 또는 참조 투 비디오 모델을 골라 시작 이미지를 넣고 움직임과 카메라 지시를 추가합니다. 15초 분량을 바로 생성하기보다 4초에서 5초 테스트로 움직임이 맞는지 확인한 뒤 길이를 늘이면, 실패한 장면에 드는 비용을 줄일 수 있습니다.

앱 화면에서는 아래 세 단계를 분리해 두는 편이 좋습니다.

- 이미지 단계에는 프롬프트, 종횡비, 참조 이미지를 둡니다.
- 영상 단계에는 시작 이미지, 영상 길이, 해상도, 오디오, 카메라 움직임을 둡니다.
- 결과 단계에는 원본 파일 내려받기, 프롬프트·설정 재사용, 생성 비용과 상태를 둡니다.

이렇게 분리하면 사용자가 이미지 생성과 영상 생성을 같은 비용으로 오해하지 않습니다. OpenHiggsfield처럼 모델 카탈로그가 설정을 결정하는 구조라면, 새 모델을 추가할 때도 각 옵션을 화면 여기저기에 중복해서 넣지 않아도 됩니다.

## 앱을 만들기 전 확인할 세 가지

첫째, 이 프로젝트는 로컬에서 모델을 직접 실행하는 도구가 아닙니다. 외부 API로 요청을 보내는 웹 스튜디오이므로 API 키, 잔액, 업로드 저장소를 준비해야 합니다.

둘째, 사용자 파일의 보관 위치를 정해야 합니다. 저장소는 업로드에 Vercel Blob을 사용하고 최근 이력은 브라우저 IndexedDB에 보관하는 구조를 설명합니다. 고객이 만든 영상과 참조 이미지를 다룬다면 파일 보존 기간, 다운로드 권한, 삭제 요청 처리를 서비스 정책에 맞춰 별도로 설계해야 합니다.

셋째, 제품 이름과 로고는 함부로 가져오면 안 됩니다. OpenHiggsfield의 코드가 공개되어 있어도 Higgsfield와 개별 모델 제공사의 상표·서비스 조건까지 함께 허용되는 것은 아닙니다. 자체 제품으로 공개할 계획이라면 저장소 라이선스, API 약관, 모델별 생성물 이용 조건을 각각 확인해야 합니다.

## OpenHiggsfield와 Higgsfield API 관련 자주 묻는 질문

**OpenHiggsfield만 설치하면 영상 생성도 무료인가요?**

아닙니다. 웹 스튜디오 코드는 별도로 내려받아 실행할 수 있지만 실제 생성은 연결한 API의 모델별 요금이 발생합니다. 저장소도 스튜디오 자체는 무료이지만 플랫폼 키가 필요하다고 안내합니다.

**Higgsfield API 키를 브라우저에 저장해도 되나요?**

권하지 않습니다. API 키는 서버 환경 변수에 저장하고 브라우저는 자체 서버에만 요청하도록 구성해야 합니다. 클라이언트 코드, 공개 저장소, 화면 캡처에는 키를 남기지 마세요.

**Seedance 2.5 15초 영상은 얼마인가요?**

하나의 고정 가격으로 답하기 어렵습니다. 텍스트·이미지·영상 참조 방식과 해상도, 오디오에 따라 청구 기준이 달라지고 실제 계산도 초당 요금이 아니라 해상도와 프레임 수를 반영한 토큰 단위로 이뤄집니다. 결제 전에는 현재 선택한 모델 설정의 가격표를 직접 확인해야 합니다.

**OpenHiggsfield는 힉스필드의 공식 오픈소스인가요?**

현재 확인되는 저장소는 `wide-trace` 계정의 공개 프로젝트이며 힉스필드 공식 도움말은 자사 플랫폼과 모델이 비공개라고 안내합니다. 두 서비스를 연결해 사용할 수 있다는 점과 코드의 공식 배포 주체는 구분해서 확인해야 합니다.

OpenHiggsfield는 영상 생성 서비스를 처음부터 설계할 때 필요한 화면과 상태 관리의 상당 부분을 보여 줍니다. 하지만 실제 운영의 난도는 프롬프트 입력창보다 키 관리, 비동기 작업 상태, 결과 파일 보관, 모델별 비용 표시에서 결정됩니다. 먼저 Soul 2로 이미지 한 장과 Seedance 2.5의 짧은 영상 한 편을 만들어 요청·완료·다운로드 흐름을 검증한 뒤, 그다음에 모델 수와 기능을 늘리는 편이 안전합니다.
